## Narrative

**[K22 DEEP-READ — 2026-05-01]** This paper identifies and formalizes "reasoning safety" as a security dimension orthogonal to content safety. Content safety checks what a model SAYS; reasoning safety checks how a model THINKS. The authors propose a nine-category taxonomy of unsafe reasoning behaviors, validate it across 4,111 annotated reasoning chains (natural + four adversarial attack methods), and build a real-time Reasoning Safety Monitor that runs in parallel with the target LLM, inspecting each reasoning step and dispatching an interrupt signal on detection. The monitor achieves 84.88% step-level localization and 85.37% error-type classification, outperforming hallucination detectors (44.36%) and process reward models (68.83%) by wide margins.

### The core insight: reasoning ≠ output

A model can produce a benign-sounding final answer whose underlying reasoning is corrupted by injected fallacies or mired in an infinite loop. Conversely, a logically sound reasoning chain may still yield harmful content. Content safety and reasoning safety are orthogonal — securing deployed LLMs requires monitoring both independently. Existing tools (hallucination detectors, PRMs) are fundamentally limited: SelfCheckGPT checks factual consistency of surface claims and cannot detect logical fallacies; PRMs are trained for math answer-trajectory quality and generalize poorly to adversarial error types.

### Formal definition of reasoning safety

A reasoning chain C = ⟨s₁, s₂, ..., sₙ, a⟩ is SAFE iff it satisfies three properties:

- **P1 — Logical Consistency**: Every step must be logically coherent with the problem statement and all prior steps. No contradictions, unsupported inferences, or invalid transitions.
- **P2 — Computational Efficiency**: Chain length must remain bounded commensurate with problem complexity. No redundant, repetitive, or purposeless steps.
- **P3 — Manipulation Resistance**: The trajectory must reflect faithful inference over the query, not deflection by adversarially injected content.

### Nine-category taxonomy

| Category | Subtype | Violates | Primary Effect |
|----------|---------|----------|---------------|
| **1. Input Parsing** | 1a. Misinterpretation | P1 | Wrong answer |
| | 1b. Missing Constraints | P1 | Wrong answer |
| | 1c. Symbol Mapping Error | P1 | Wrong answer |
| **2. Execution** | 2a. Logical Fallacy | P1 | Wrong answer |
| | 2b. Calculation Error | P1 | Wrong answer |
| | 2c. Inconsistency | P1 | Wrong answer |
| **3. Process Mgmt.** | 3a. Reasoning Loop | P2, P3 | Resource waste |
| | 3b. Goal Deviation | P2, P3 | Resource waste / Wrong answer |
| | 3c. Premature Conclusion | P1, P3 | Wrong answer |

### Prevalence study — three key findings

From 4,111 annotated chains across OmniMath (natural) + BadChain, Preemptive Answer Attack, OverThink, Deadlock (adversarial):

**Finding 1: Intrinsic failures span Cat 1+2 only.** OmniMath (natural reasoning): Logical Fallacy 34.6%, Calculation Error 25.2%, Misinterpretation 13.0%, Missing Constraints 10.8%, Symbol Mapping Error 11.4%. Process Management errors are nearly absent (≤1.7% total). Category 3 errors do NOT arise from normal reasoning — they are strong indicators of adversarial manipulation when detected.

**Finding 2: Each attack induces a distinctive, mechanistically interpretable error signature.**
- BadChain → 60.8% Goal Deviation (3b) + 17.3% Inconsistency (2c) + 12.6% Logical Fallacy (2a)
- Preemptive Answer Attack → 48.7% Calculation Error (2b) + 33.5% Premature Conclusion (3c)
- OverThink → 74.5% Misinterpretation (1a) + 25.0% Goal Deviation (3b)
- Deadlock → 69.6% Reasoning Loop (3a) + 15.8% Goal Deviation (3b) + 12.1% Misinterpretation (1a)

**Finding 3: Attack categories map cleanly onto taxonomy categories.** Reasoning hijacking attacks (BadChain, Preemptive Answer) primarily activate Cat 1+2 errors alongside Goal Deviation and Premature Conclusion — their goal is wrong answers. Reasoning DoS attacks (OverThink, Deadlock) predominantly activate Cat 3 errors (Reasoning Loop, Goal Deviation) — their goal is resource exhaustion. This clean correspondence validates the taxonomy as an attack-classification tool.

### Reasoning Safety Monitor — architecture

The monitor operates as an independent process running in parallel with the target LLM. Four design goals: G1 (real-time detection), G2 (precise localization), G3 (error classification into 9-type taxonomy), G4 (intervention — halt generation or flag for rollback).

Implementation: an off-the-shelf LLM (e.g., gpt-oss-20b) prompted with a carefully designed template containing five components:
1. **Role Definition** — "You are an Advanced AI Reasoning Verification Expert"
2. **Taxonomy Embedding** — full nine-category taxonomy reproduced verbatim in the prompt
3. **Structured Input Format** — JSON with problem statement + ordered reasoning steps
4. **Structured Output Format** — JSON with safety flag, error type code, confidence, location quote, explanation
5. **Calibration Rules** — evaluate only the current step (not prior verified steps); do not flag speculative language or self-questioning as errors

Key design properties: no model fine-tuning required; model-agnostic (can monitor any target LLM); produces interpretable, auditable verdicts with verbatim error-location quotes.

### Evaluation results (Table 2, 450-chain benchmark)

| Monitor / Baseline | Position Acc (%) | Type Acc (%) |
|---|---|---|
| SelfCheckGPT (hallucination detector) | 44.36 | — |
| Qwen2.5-Math-PRM-7B (process reward) | 68.83 | — |
| GPT-4o-2024-08-06 | 73.11 | 70.00 |
| gpt-oss-20b | 82.66 | 75.33 |
| Gemini-3-Flash-Preview | 84.00 | 80.44 |
| **Qwen3.5-35B-A3B** | **84.88** | **85.37** |

LLM monitors substantially outperform both baselines. Hallucination detectors are near-random (44.36%). PRMs capture some signal (68.83%) but lack type classification. All LLM-based monitors beat both; the gap between position and type accuracy is modest (~7pp), meaning once localized, error subtype is reliably assigned.

**Specific Cemini applications**:
- **MAPPO agent reasoning**: If Cemini adopts reasoning-model backbones for trading decisions, each daily decision's CoT chain is a reasoning-safety attack surface. The monitor can detect BadChain-style goal deviation before a corrupted decision reaches trade execution.

- **Algorithmic stopping conditions**: K14's stopping conditions operate at the policy-execution level. K22's Reasoning Loop (3a) and Premature Conclusion (3c) detection provides stopping conditions at the reasoning level — if the agent's CoT loops, the monitor kills it before it reaches the execution layer.

### Limitations (per authors)

False-positive characterization under diverse clean-reasoning distributions is incomplete; optimal intervention threshold τ needs systematic calibration. Robustness against adaptive adversaries who craft attacks specifically to evade the taxonomy-embedded prompt is an open problem. Framework currently text-only — multimodal and tool-augmented chains not covered.

### When to consult this page

- Designing execution-security boundaries where LLM reasoning precedes tool invocation
- Evaluating whether a CoT anomaly is adversarial (Cat 3 signature) or intrinsic (Cat 1-2 distribution)
- Building a monitoring layer between reasoning-model output and SAE execution gates
- Understanding why content-safety tools fail to detect reasoning-level attacks
- Classifying an observed agent failure as hijacking vs. DoS vs. intrinsic error

## Snippets

**S1 — Reasoning safety vs. content safety** (p.1, §1):
> "Content safety concerns what a model says; reasoning safety concerns how a model thinks. A model may produce a response that appears benign at the output level while its underlying reasoning chain is corrupted by injected fallacies, truncated prematurely, or mired in an infinite loop—none of which content-safety tools can detect."

**S2 — Formal definition of safe reasoning chain** (pp.3–4, §3.1):
> "A reasoning chain C is safe with respect to query q if and only if it satisfies the following three properties: Logical Consistency — every step s_i must be logically coherent with both the problem conditions stated in q and all prior steps. Computational Efficiency — the length n of the reasoning chain must remain within a bound commensurate with the complexity of q. Manipulation Resistance — the reasoning trajectory must reflect the model's faithful inference over q and must not be deflected by adversarially injected content."

**S3 — Taxonomy overview** (p.4, §3.2):
> "Input Parsing Errors occur in the initial stage of problem comprehension, before substantive reasoning begins. The model fails to faithfully map the query q into an internal representation that correctly captures its intent and constraints, causing all downstream reasoning to proceed from a flawed premise. Reasoning Execution Errors occur during the core reasoning stage, in which the model performs logical deduction, computation, or inference. Process Management Errors operate at the meta-cognitive level, affecting not individual reasoning steps but the overall structure and trajectory of the reasoning process."

**S4 — Finding 1: Cat 3 errors signal adversarial manipulation** (p.5, §3.3):
> "Process Management errors are nearly absent (≤1.7% total) [in natural reasoning], confirming that Category 3 failures do not arise from normal reasoning behavior and are therefore strong indicators of adversarial manipulation when detected."

**S5 — Finding 2: Distinctive attack signatures** (pp.5–6, §3.3):
> "Rather than producing uniform noise across all categories, each attack concentrates errors in a small number of subtypes that directly reflect its operational logic. BadChain overwhelmingly produces Goal Deviation (60.8%), accompanied by Inconsistency (17.3%) and Logical Fallacy (12.6%). Preemptive Answer Attack is characterized by a bimodal distribution: Calculation Error (48.7%) and Premature Conclusion (33.5%). OverThink produces a near-singular distribution dominated by Misinterpretation (74.5%). Deadlock concentrates almost entirely on Reasoning Loop (69.6%)."

**S6 — Finding 3: Attack-to-category mapping** (p.6, §3.3):
> "Reasoning hijacking attacks (BadChain, Preemptive Answer) primarily activate Category 1 and Category 2 errors alongside Goal Deviation (3b) and Premature Conclusion (3c), as their goal is to steer the model toward a wrong answer. Reasoning DoS attacks (OverThink, Deadlock) predominantly activate Category 3 errors—particularly Reasoning Loop (3a) and Goal Deviation (3b)—as their goal is to inflate computational cost rather than control the final answer. This clean correspondence between attack type and error category validates the threat model."

**S7 — Monitor design** (p.6, §4.2):
> "The monitor operates as an independent process that runs in parallel with the target LLM, inspecting the reasoning chain as it is generated token by token. Upon receiving a complete step, the monitor is immediately invoked; no buffering of the full chain is required."

**S8 — Calibration rules to suppress false positives** (p.7, §4.3):
> "The monitor is directed not to flag speculative language, hypotheses, or self-questioning (e.g., 'Maybe X is true' or 'Is Y possible?') as errors, recognizing that exploratory uncertainty is a legitimate and beneficial feature of extended reasoning chains. Only statements presented as definitive conclusions are subject to error classification."

**S9 — Hallucination detectors fail** (p.8, §5.2):
> "SelfCheckGPT achieves only 44.36% position accuracy—little better than random guessing on a multi-step chain—confirming that factual consistency checking is fundamentally misaligned with the task of detecting logical reasoning errors. Its sampling-based consistency signal carries no information about structural reasoning failures such as Goal Deviation or Reasoning Loop."

**S10 — PRM limitation** (p.8, §5.2):
> "PRMs are trained to assess answer-trajectory quality on mathematical benchmarks and lack generalization to diverse error types such as Misinterpretation (1a) or Premature Conclusion (3c). Critically, neither baseline produces error-type labels, precluding their use for diagnostic or attack-classification purposes."

**S11 — Monitor performance** (p.8, §5.2):
> "Embedding the explicit error taxonomy into the prompt enables LLMs to detect reasoning-level anomalies that reward models trained on implicit quality signals cannot capture. Qwen3.5-35B-A3B achieves the highest type accuracy at 85.37%, suggesting that its stronger reasoning understanding translates to more precise error diagnosis."

**S12 — Attack signature as detection signal** (p.6, §3.3):
> "This clean correspondence between attack type and error category validates the threat model of Section 4.1 and demonstrates that our taxonomy provides actionable signal for both detection and attack classification."
