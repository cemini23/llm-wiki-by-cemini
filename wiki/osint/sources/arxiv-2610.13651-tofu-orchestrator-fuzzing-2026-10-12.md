## Narrative

**The premise: tool arguments generated by an LLM must be treated as untrusted.** The orchestration layer interprets model output as executable calls — that is the boundary the paper attacks.

### The attack

**Repeat-After-Me.** The attacker supplies text **in the tool-call format** and asks the LLM to **repeat it**. The orchestrator dispatches the repetition as a real call. No jailbreak needed — only a "repeat this".

### The tool — ToFu

- **Semantic security checks derived from tool metadata.**
- A **CWE-guided sanitizer corpus** — **74 semantics-aware sanitizers**.
- **Auto-generated schema-valid fuzzing harnesses and semantic oracles** via runtime introspection and outcome sanitization. **The LLM is not the oracle** — the oracle is derived from the tool's own semantics.

### The results (the scale matters)

**273 MCP servers / 3,405 tools** evaluated. **253 verified bugs across 343 tools in 118 servers** — including **path traversal (CWE-22)**, **XSS (CWE-79/116)**, exfiltration, log injection, and **SQL injection**.

### Why it matters here

This is the **sharpest MCP-security result in the wiki's record** — a **~42% server hit rate** on a 273-server sweep. Two things to carry: (1) **the fuzz oracle must be the tool's semantics, not a model** (same doctrine as NOMOS, K288); (2) **"repeat this" is an attack** — an agent that will echo tool-call-shaped text will execute it. Extends `agent-setup-instruction-supply-chain`. **No PoC, no exploit steps, no payloads.**
