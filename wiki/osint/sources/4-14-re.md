## Narrative

Cemini internal research digest that evaluates a heterogeneous set of external projects — academic papers, open-source repos, ML models — against the rigid constraints of the production stack (Hetzner Ubuntu 24, CPU-only, 128GB RAM, Python 3.12/FastAPI/Redis Streams, Pydantic v2, 34-dim feature vector, 5-agent MAPPO, 62K params per agent, FastMCP with 24 tools on port 8002, IP-sale target). Each section follows an eight-slot template: (1) what is this, (2) architecture patterns worth stealing, (3) algorithms worth evaluating, (4) code/tooling worth examining, (5) what they got wrong or overcomplicated, (6) IP-sale relevance, (7) solo-dev effort filter (🟢 LOW / 🟡 MEDIUM / 🔴 HIGH), (8) conflicts with deployed stack.

**Sections observed:**
1. **Agent Q-Mix / MARL topology routing** — QMIX monotonic value factorization + discrete communication action space (solo_process, broadcast_all, selective_query, aggregate_refine, execute_verify, debate_check) mapped to Redis-Streams XADD. Recommends adopting the discrete-action head on the 62K MAPPO policy; rejects the GNN for 5-node graph as massive overkill (5×5 adjacency → flat MLP is trivially sufficient). Medium effort (1–2 days).
2. **C3AN / Deterministic Schema Enforcement** — validates existing Pydantic v2 choice; maps the framework onto Devil's Advocate debate protocol; rejects "Golden Dataset" static validation in favor of streaming validation against live TimescaleDB windows. Low effort (<4h).
3. **Exqutor + Maximally Informative Binarization (MIB)** — proposes binary-quantized pgvector bit(34) / bit(1088) with hamming_distance for text embeddings only; explicitly warns against binarizing the MAPPO 34-dim numerical feature vector (catastrophic info loss). Rejects Exqutor's PostgreSQL-planner C-extension modification as brittle for solo dev — executes adaptive LIMIT/TABLESAMPLE in FastAPI Python instead. Medium effort.
4. **Memelang / MemoriesDB / axial grammar** — adopts the "time-indexed stack of temporal-semantic surfaces" pattern for TimescaleDB + pgvector; rejects the bespoke axial DSL in favor of JSON + grammar-constrained decoding (outlines, llama.cpp grammar); warns against JSONB-heavy edges on the hot path. Merkle-tree hash in relational columns for audit trail. Low effort.
5. **FastMCP tooling ecosystem** — prescribes "Progressive Disclosure" from Anthropic Skills: 24 FastMCP tools must initially surface as ~100-token metadata stubs, with full Pydantic schema fetched via semantic ToolSearch only on demand (saves ~12KB per request, avoids LLM auto-compress). MCPHub vector-semantic routing evaluated for FastMCP router. Claude Inspector MITM proxy for local prompt-intercept analysis.

Consistent editorial pattern across sections: (i) IP-sale relevance explicitly scored; (ii) solo-dev effort filter hard-enforced (GNN over 5 nodes = reject; custom PostgreSQL C-extensions = reject; custom DSL grammar = reject); (iii) CPU-only constraint is load-bearing for every architecture decision.

- Reject axial-grammar DSL; use JSON + grammar-constrained decoding (outlines, llama.cpp).

## Snippets

- **Agent Q-Mix / GNN rejection** — "Applying complex graph convolutions to a 25-element matrix introduces unnecessary computational overhead and fails the solo-developer simplicity filter. A simple flattened representation of the adjacency matrix passed through a standard Multi-Layer Perceptron (MLP) will achieve identical structural awareness."
- **C3AN** — "By defining the debate rubric as strict Pydantic v2 schemas, the subjective outputs of the 5-agent heterogeneous ensemble are forced through a deterministic canonicalization engine."
- **MIB warning** — "Binarizing this specific tensor to 34 bits (~4 bytes) will likely cause catastrophic information loss, destroying the agent's ability to discern subtle market regimes. The binarization technique must be strictly isolated to the FastMCP text and news embeddings."
- **Exqutor rejection** — "maintaining custom C-extensions for PostgreSQL creates a brittle CI/CD pipeline… The adaptive sampling mechanism should be executed entirely in Python 3.12 application space via FastAPI."
- **Memelang rejection** — "it is infinitely more stable to rely on standard JSON constrained by programmatic Grammar-Constrained Decoding (e.g., outlines or llama.cpp grammar features) than to invent, parse, and maintain a proprietary language."
- **Progressive Disclosure** — "tools must initially load only as metadata stubs (~100 tokens), and the LangGraph brain orchestrator must execute a semantic ToolSearch to fetch the full JSON schema only when a specific tool is required."
