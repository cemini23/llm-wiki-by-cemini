## Narrative

XSKILL addresses two well-known bottlenecks in multimodal-agent (MLLM) systems: **inefficient tool use** (excessive steps on simple problems, insufficient depth on complex ones) and **inflexible tool orchestration** (single-path execution, limited cross-task composition). The proposed fix is a **dual-stream knowledge architecture** that lets agents continually improve without parameter updates by accumulating two complementary forms of knowledge from past trajectories.

### The dual-stream architecture

| Stream | Storage | Purpose | Granularity |
|--------|---------|---------|-------------|
| **Skills** | Markdown library (`SKILL.md` per skill) | Task-level guidance: structured workflows + tool templates | Procedure |
| **Experiences** | JSON-backed Experience Bank | Action-level insights: tactical guidance for tool selection, exploration, error recovery | Decision |

Two specialized MLLM instances divide labor:
- **MLLMexec** runs tool-use inference (the agent proper)
- **MLLMkb** handles knowledge-base operations: extraction, consolidation, adaptation

Privilege separation between them allows a stronger model to do knowledge management (which is rarer and more important to get right) while a flexible/cheaper model executes. **Cross-model knowledge transfer**: knowledge accumulated by one model can benefit another — the experiments demonstrate Gemini-3-Flash-accumulated knowledge boosting GPT-5-mini and o4-mini.

### Two-phase loop

**Phase I — Accumulation** (training-time, on `D_train`):

1. **Multi-path rollouts** — agent attempts each task N times
2. **Rollout summary** — distill each trajectory into structured output
3. **Cross-rollout critique** — compare successful vs failed rollouts, extract "insight from comparison" + "insight from commonalities"
4. **Hierarchical consolidation**:
   - Skill manager: workflow extraction → tool template extraction → skill document generation → length filter → MLLM judgement → Skill Library
   - Experience manager: similarity filter → quantity filter → MLLM judgement → Experience Bank

**Phase II — Inference** (test-time, on `T_test`):

1. **Decomposition** — break query into subtasks
2. **Retrieval** — top-k semantic match against Skill Library + Experience Bank (the paper uses `text-embedding-3-small`, top-k=3)
3. **Adaptation** — visually ground retrieved knowledge to current visual context (experience rewrite + skill adaptation)
4. **Injection** — system-prompt injection feeds adapted knowledge to the executing agent

### Empirical performance

Evaluated on **5 benchmarks** across 3 domains, with **4 backbone models**:

| Benchmark | Domain |
|-----------|--------|
| VisualToolBench | Visual agentic tool use |
| TIR-Bench | Tool-integrated reasoning |
| MMSearch-Plus | Multimodal search |
| MMBrowseComp | Multimodal browsing |
| AgentVista | Comprehensive (tool use + search) |

Backbones: Gemini-2.5-Pro, Gemini-3-Flash, GPT-5-mini, o4-mini (+ Qwen3-VL-235B/32B in appendix).

Results (Average@4 / Pass@4 over 4 rollouts):

- **+2.58 to +6.71 Avg@4 points** over tool-only baseline across all backbones
- **+11.13 points on TIR-Bench** with Gemini-3-Flash vs strongest learning-based baseline (Agent-KB)
- Cross-model transfer: **+2.58 to +4.16 points** for GPT-5-mini and o4-mini using Gemini-3-Flash-accumulated knowledge

Compared to learning-from-experience baselines (Agent Workflow Memory, Dynamic Cheat-Sheet, Agent-KB), XSKILL outperforms in most settings, with biggest gains on tasks requiring complex visual reasoning + multi-step tool composition.

### Why this matters for Cemini

XSKILL's dual-stream architecture maps onto Cemini's existing infrastructure with surprising fidelity:

| XSKILL component | Cemini analog | Status |
|------------------|---------------|--------|
| Skill Library (Markdown) | `wiki/concepts/` (Markdown procedure pages) | Already deployed; XSKILL validates the pattern |
| Experience Bank (JSON) | stash episodic memory layer (per `@sources/alash3al-stash.md`) | Already deployed; stash uses Postgres+pgvector vs JSON but same role |
| MLLMexec / MLLMkb separation | DeepSeek (analyst) + future heavier model for knowledge mgmt | Conceptual fit; not currently split this way |
| Cross-rollout critique | Conductor v0.1.1 routing-decision logging + future autoresearch loop | Atlas-gic clean-room re-implementation brief is the closest active workstream |
| Subtask decomposition + top-k retrieval | kb-server REST API over wiki + stash recall MCP tools | Already deployed |
| Visual grounding | Not currently in Cemini's stack (we're not multimodal yet) | Out-of-scope until/unless we ingest charts/screenshots |

The most actionable take-away: **the cross-rollout critique mechanism** is the missing piece in Cemini's autoresearch evolution. The atlas-gic brief (`@briefs/2026-05-04_autoresearch-conductor-evolution.md`) describes a Sharpe-loss + git-commit/revert loop; XSKILL describes a parallel approach using MLLM-judged comparison of multiple rollouts to extract insights without code-mutation. The two could be combined: Conductor's routing-decision logs become the rollout corpus that gets MLLM-critiqued (XSKILL-style) to generate refined routing rules (atlas-gic-style git commit).

### What we don't take from XSKILL

- **Visual grounding** — Cemini's threat surface is text + numerical (financial APIs, market data, prediction-market contracts). Until we ingest visual data (charts, dashboards, screenshots), the visual-grounding parts of XSKILL don't apply.
- **Specific benchmark optimizations** — XSKILL is tuned for VisualToolBench / TIR-Bench / MMSearch-Plus / etc. Cemini's eval surface is financial backtests and prediction-market Brier scores; the benchmark-specific optimizations don't transfer.

## Snippets

- **Dual-stream framing**: "We identify two complementary forms of reusable knowledge essential for this goal: experiences, providing concise action-level guidance for tool selection and decision making, and skills, providing structured task-level guidance for planning and tool use." [Source: XSKILL §1 Abstract]

- **Cross-model transferability**: "GPT-5-mini and o4-mini gain 2.58 to 4.16 points over the tool-only baseline, suggesting that externalized knowledge structures remain effective across different model architectures without requiring model-specific accumulation." [Source: XSKILL §3.2]

- **MLLMexec/MLLMkb separation rationale**: "This separation allows using a stronger model for knowledge management while keeping the execution model flexible, and enables cross-model knowledge transfer where knowledge accumulated by one model can benefit another." [Source: XSKILL §2 Methodology]

- **Cross-rollout critique mechanism**: "Phase I (accumulation), given a training dataset Dtrain, the agent performs multiple rollouts and employs visually-grounded summarization and cross-rollout critique to extract skills and experiences." [Source: XSKILL §2 Methodology]

- **Big TIR-Bench delta vs Agent-KB**: "On TIR-Bench with Gemini-3-Flash, our method achieves 47.75% Average@4, surpassing the strongest baseline Agent-KB by 11.13 points." [Source: XSKILL §3.2]
