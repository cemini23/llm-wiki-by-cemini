## Narrative

As LLMs become front-door control components in agentic expert systems, **structured routing** — emitting a machine-readable control record deciding which subsystem handles a request, whether memory is queried, whether a tool fires — must balance correctness, latency, and implementation cost under real deployment constraints. The paper reframes structured routing, usually treated as a prompt-engineering problem, as a **systems-level runtime burden-allocation problem**: every deployment profile allocates structural work differently across the generation stack — output structure can be emitted directly by the model, **compressed during transport**, or **reconstructed locally** in deterministic software after generation. Other axes include streaming vs non-streaming transport, requiring final JSON vs accepting a shorter intermediate code, and generation-budget relaxation.

The authors run a **full-factorial cross-backend benchmark**: 48 deployment configurations and 15,552 requests across **OpenAI, Gemini, and Llama** backends. The central finding: **there is no universal best routing mode** — backend-specific interaction effects dominate. Modes that stay highly reliable on Gemini and OpenAI can suffer substantial correctness degradation on Llama, and efficiency gains from compressed realization are strongly backend-dependent. Rather than another isolated model comparison, the contribution is a **deployable methodology**: a cross-backend evaluation framework plus practical deployment guidance for navigating the correctness–cost–latency frontier, treating low-level packaging choices (streaming, schema-burden placement, local reconstruction) as first-class expert-system design variables.

**Cemini relevance**: directly conductor-relevant — the conductor *is* a structured LLM router, and this work shows routing-mode choices must be tuned per backend; "no universal best mode" is a concrete design constraint for any multi-backend routing layer.
