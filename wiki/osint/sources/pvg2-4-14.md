## Narrative

MemoriesDB is a unified data architecture for long-term agent memory designed to avoid **decoherence** — the drift of facts, intentions, and reasoning continuity as an LLM agent operates over hours-to-weeks. Its thesis: existing approaches each capture only one axis — vector databases store meaning but not time or structure, time-series stores capture sequence but not semantics, graph databases encode topology but lack a similarity metric. MemoriesDB fuses all three. Each memory is a *time–semantic–relational entity*: a tuple `M = (t, κ, V, m)` where `t` is a unique microsecond timestamp (the discrete indexing axis), `κ` a kind label, `V` a multi-view set of normalized sub-embeddings (coarse low-dim + fine high-dim, optionally lexical/trigram), and `m` a JSONB metadata map. Directed labeled edges `(Mi→Mj, ρ, W, m)` carry per-edge weight (strength + confidence) and metadata, forming a directed multigraph.

Geometrically, each memory owns a local plane parameterized by `(Δt, Δs)`; the database is an ordered *stack of temporal–semantic surfaces* with edges projecting as directional arrows in a 1+1-dimensional similarity field — a fibered graph with time as base coordinate. Coherence between two memories is `Cpair = e^(−d)`, and a windowed local-coherence signal flags drift. Queries constrain along temporal window, semantic vector, and relational filter simultaneously, with a combined importance score `S = α·sim + β·e^(−Δt/τ) + γ·Φ`. The whole formalism is realized pragmatically on **PostgreSQL 16 + pgvector** with an append-only schema (`memories` and `edges` tables, IVFFlat vector index, B-tree time index, GIN on JSONB), per-agent schema namespacing, and an inner-product operator (`<#>`) as a fast cosine proxy on normalized vectors. The paper is honest that performance figures are *illustrative estimates, not formal benchmarks* (single insert ~1.9–2.5 ms, batch insert ~8–10k recs/s on a 32-core/128 GB box); coherence stability at 100M records is left to future work. Roadmap: columnar Parquet backend, distributed sharding, GPU batch similarity.

**Cemini relevance**: MemoriesDB is a candidate substrate for agent long-term memory and overlaps directly with the librarian/stash episodic-memory layer — notably its time+semantic+relational fusion on commodity PostgreSQL+pgvector, the same infrastructure the kb-server retrieval layer already uses. The append-only, audit-friendly design and per-agent namespacing are relevant patterns; the unbenchmarked claims keep it `[TENTATIVE]`.
