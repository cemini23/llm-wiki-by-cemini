## Narrative

Cemini-internal architecture audit structured as 5 questions, each with Evidence + Implementation Sketch + Risk/Gotcha. Written from the solo-developer perspective, explicitly framed for IP-sale technical due diligence. Dated ~2026-03-26 (all "accessed March 26, 2026" works-cited dates).

**Q1 — Mobile-controlled 24/7 autonomous agents**: Prescribes event-driven decoupling via FastAPI webhooks → Redis Streams → LangGraph interrupt()/Command(resume=...) on PostgresSaver. Mobile gateway via Twilio SMS or Telegram. **Risk**: SMS is a due-diligence failure for institutional buyers (SIM-swap). **Upgrade path**: OIDC/CIBA push-notification auth instead of SMS. Effort 4-5 days.

**Q2 — LLM agent reliability (retry, fallback, graceful degradation)**: Cites the MAST study's "Compound Reliability Decay" — 5-agent chain at 90% per-step = 59% end-to-end. Prescribes: max 5-step chains, Pydantic validation nodes after every LLM generation, LangGraph RetryPolicy for HTTP errors, circuit breaker at 3 retries, fallback to **programmatic heuristics** (NOT to a smaller LLM — smaller model = same failure, just faster). Token-burn circuit breaker at 50K tokens/task.

**Q3 — Financial MCP servers**: Evaluates FMP (SOC 2, 70K+ endpoints, commercial, strongest for IP sale), AlphaVantage (MIT, technical indicators), Octagon AI (deep research, SEC parsing), SEC EDGAR MCP (MIT, community). Recommends FMP as primary integration. **Risk**: context window saturation from raw 10-K dumps; GPL/AGPL license contamination from community MCP servers.

**Q4 — Local LLM on CPU (7B-14B)**: DeepSeek-R1-14B Q5_K_M on high-end CPU = 8.8–11.3 t/s. R1-32B at Q4 = 4.3 t/s. Critical constraint: memory bandwidth, not compute. NUMA dual-socket = worse than single-socket due to cross-die matrix multiplication overhead. Implementation: Ollama in Docker with strict `cpuset` + `mem_limit` cgroups. **Risk**: TTFT (Time-to-First-Token) on large prompts = dozens of seconds → local models must be restricted to short-context tasks only. Resource starvation of TimescaleDB if cgroups aren't enforced.

**Q5 — Hybrid cloud/local coordination**: Hierarchical Supervisor routing — lightweight semantic router dispatches: sentiment/keyword/news → local DeepSeek (free); risk/strategy/debate/execution → cloud Claude (paid). Coordination via PostgreSQL "Shared Scratchpad" — local model writes pre-processed sentiment to DB, cloud model reads it. Claims 30-70% cost reduction. **Risk**: local model JSON schema non-compliance (DeepSeek-R1 injects markdown into structured output); async blocking — local LLM must run on independent Celery/RQ worker, not block the main LangGraph thread.

**Synthesis — Top 3 Actionable Findings**:
1. Replace SMS with OIDC/CIBA FastAPI dashboard (4-5 days) — highest IP-sale value impact
2. Docker cgroups isolation for local LLM (4-6 hours) — prevents TimescaleDB starvation
3. Runtime circuit breakers + loop detection (2-3 days) — pre-requisite for 24/7 autonomous operation

**Blind Spots**:
1. PostgreSQL checkpoint state bloat — LangGraph saves full state at every node transition; 24/7 operation = exponential DB bloat. Requires pruning/compression/archival.
2. Sandbox security for LLM-generated code — if agents generate Python/SQL, execution must be sandboxed (safe-py-runner or ephemeral Docker).
3. TorchRL↔LLM latency synchronization — RL loop expects ~100ms observation tensor updates; local CPU LLM at 10 t/s creates a 10-100× mismatch. Async buffer needed.

## Snippets

> "Institutional buyers penalize systems reliant on non-deterministic state management, insecure control planes, and copyleft licensing (such as GPL/AGPL dependencies) that threaten proprietary trading algorithms." [Source: 3_26 b.docx §1]

> "According to the Multi-Agent System Failure Taxonomy (MAST) study, 'Compound Reliability Decay' is a primary failure mode in production. Because agent success rates are multiplicative, a chain of five sequential LLM decisions, each with a 90% success rate, possesses an end-to-end reliability of merely 59%. To combat this, production architectures enforce a maximum sequence of 3 to 5 steps before forcing the output through a deterministic, programmatic verification node." [Source: 3_26 b.docx Q2]

> "If a 200B+ parameter model like Claude fails a complex reasoning task, routing the exact same prompt to a local 14B model will almost certainly result in another failure, simply executing faster and cheaper. True graceful degradation must route to programmatic, non-LLM algorithmic heuristics (e.g., falling back to standard momentum indicators) or directly to a human operator." [Source: 3_26 b.docx Q2 Risk/Gotcha]

> "The primary risk in this architecture is the profound security vulnerability inherent in SMS-based or standard Telegram authorization protocols. While perfectly acceptable for a solo-developer proof-of-concept or paper trading mode, an institutional buyer evaluating the IP will immediately flag SMS trade execution authorization as a critical failure due to the prevalence of SIM-swapping attacks." [Source: 3_26 b.docx Q1 Risk/Gotcha]

> "LangGraph's PostgreSQL checkpointers save the entire conversation array and internal state dictionary at every single graph step. In a 24/7 continuous trading system, this will cause catastrophic database bloat within PostgreSQL, rapidly consuming the storage capacity of the VPS. The developer must proactively implement a cron job to prune legacy thread_id states or utilize LangGraph's state summarization patterns to compress older working memory into pgvector embeddings before deleting the raw state rows." [Source: 3_26 b.docx Q1 Risk/Gotcha]

> "A 14B model quantized to Q5_K_M requires roughly 10GB of RAM. Generating 10 tokens per second requires the CPU to pull that 10GB across the memory bus 10 times a second, saturating standard DDR4/DDR5 channels. Furthermore, llama.cpp and similar frameworks struggle with scaling across dual-socket CPU systems due to NUMA architecture." [Source: 3_26 b.docx Q4]

> "Financial Modeling Prep (FMP) stands out as the definitive, production-ready enterprise MCP server, offering the most comprehensive access to global equity data, SEC filings, and real-time market metrics. [...] For systems targeting an IP sale, FMP represents the highest value integration due to its SOC 2 compliance, native MCP support, and avoidance of open-source copyleft licensing contamination." [Source: 3_26 b.docx Q3]

> "Organizations deploying AI model routers report 30% to 70% cost reductions by intelligently directing queries to the most cost-effective model capable of handling the specific task. A simple data extraction query can be routed to a lightweight local model, while multi-step reasoning tasks demand a flagship cloud model; the router makes this determination in milliseconds." [Source: 3_26 b.docx Q5]
