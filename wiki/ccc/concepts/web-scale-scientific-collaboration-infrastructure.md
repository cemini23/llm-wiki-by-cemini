## Raw Concept

Question: how should autonomous research infrastructure coordinate open networks of agents, humans, and resources — not just closed single-agent execution loops?

## Narrative

**Web-scale scientific collaboration infrastructure** [TENTATIVE — Clarus 2606.30246]: research as **project–agent–resource** coordination under sparse feedback, open-ended objectives, and distributed cognition/resources.

**Four system gaps Clarus targets:**

1. **Agent as network participant** — identity, capabilities, reputation, resource access (not just assistant)
2. **Auditable collaboration** — evidence chains, failure paths, decisions for reproduction
3. **Open discovery/negotiation** — dynamic capability matching vs fixed subagent roster
4. **Physical grounding** — labs, instruments, private data beyond API calls

**Four layers:** Research Application → Digital Collaboration → Physical Substrate → Physical World.

**Steal-from for Cemini harness:**

| Clarus primitive | CCC analogue |
|------------------|--------------|
| Project phases/tasks | `/goal` + OpenSpec + ingest matrix stages |
| Agent participants | Cursor subagents, conductor, sibling wikis as federated agents |
| Resource objects | MCP servers, egress-fi archive, prod-mcp tunnel |
| Provenance/credit | `wiki/log.md`, source pages, bidirectional `related:` |
| Open network vs dark forest | Cross-wiki routing + Phase-0 license audit |

**Contrast:** PaperClaw/XCIENTIST/deep-scientist = **closed research harnesses**; Clarus = **collaboration substrate** for many such harnesses. **REFERENCE** only — no SaaS prod mount without ToS audit.
