## Narrative

**The operator problem it names.** Generative edit sliders feel broken. Dragging a strength control produces dead zones where nothing changes, then a jump, then a reversal — because the slider value is being fed directly to an internal strength parameter that has no linear relationship to what the eye sees. The paper separates the **user-facing slider** from the **internal strength** and trains a small adapter so perceptual distance grows linearly with the slider value.

**Method (training-based, not training-free).** A rank-32 LoRA on the attention projections of every block of a **Flux.2-Klein-4B** few-step editing DiT, scaled so the adapter vanishes at full strength. Training runs the full 4-step sampler in the loop and optimizes a pixel-space **DreamSim** loss that pushes perceptual distance to be proportional to s. There are no ground-truth intermediates — the training target is the cached frozen-backbone output. Training data is 300 MIT-Adobe-FiveK images with instructions auto-generated by Qwen3-VL-30B. An inference-time **adaptive-sampling remap** then closes residual non-uniformity with no extra training.

**Results.** On a new 300-edit benchmark it beats SliderEdit, Kontinuous Kontext, DiffusionSteering, FlowSlider, VeloEdit and Firefly Tune. Uniformity CV-DSim 0.652 against 0.675 for the next best; monotonicity VLPIPS 0.016 against 0.078, about **5x better**. The user study wins 82% of two-alternative comparisons.

**Phase-0 (2026-10-07).** Project page only (`color.cvc.uab.cat/unislider`) — **no GitHub URL, no licence, code and weights not confirmed released**. Training was about 2 h on one RTX PRO 6000, producing an 8 MB adapter; 11-frame inference takes 7.02 s. Consumer VRAM is not stated.

**Why it is only WATCH-thin.** The want is real — sliders that feel linear would improve any operator-facing editing UI. But the method is **tied to a few-step backbone** (Flux.2-Klein-4B, not SDXL or FLUX.1), it requires a **2 h training run per backbone**, and it backprops through a 4B model's full sampler, so low-VRAM feasibility is unverified. With no released code, adopting it today means reproducing the training recipe.
